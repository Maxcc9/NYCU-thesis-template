\chapter{Introduction}
\label{ch:intro}

近年來，支撐檢索、推薦、語意搜尋與多模態理解的向量資料庫規模快速擴張，
使得 Approximate Nearest Neighbor Search（ANNS）成為大規模系統中的核心操作之一。
在億級以上的資料集上，若仍以精確最近鄰搜尋處理每一筆查詢，計算成本與延遲都會迅速失控，
因此研究社群逐步轉向局部敏感雜湊\cite{datar2004lsh}、圖式索引\cite{malkov2020hnsw,fu2019nsg}與量化近似\cite{jegou2011pq}等方法，以在 recall 與 throughput 之間取得平衡\cite{subramanya2019diskann,chen2021spann}.

DiskANN 是其中最具代表性的磁碟式 graph-based ANNS 系統之一，並已被整合進實際的向量資料庫與雲端服務\cite{wang2021milvus,upreti2025cosmos}。
它以 Vamana 圖為核心，透過 PQ 壓縮與 beam search 在單節點上支援百萬到十億級規模的查詢，
在記憶體使用量上相對節制，但查詢過程仍需要大量隨機磁碟 I/O。
尤其當企業將 RAG 等 agent 服務部署於地端、由多個使用者併發觸發檢索時，資料集規模與並發查詢同時上升，這些隨機讀取便成為主要瓶頸，導致系統難以同時維持高 recall、低延遲與高吞吐量\cite{subramanya2019diskann}.

Starling 則嘗試從 page layout 的角度改善這個問題。
它透過 block shuffling 與 in-memory navigation graph 提高每次 page read 的資訊密度，
降低無效 I/O 的比例，因而在靜態索引與中等 recall 設定下能取得顯著加速\cite{wang2024starling}.
然而，Starling 的優勢高度依賴資料布局與導覽圖品質；一旦面對 streaming update、
記憶體預算下降或高併發 CPU 飽和等場景，其效益並不一定能維持。

本研究提出 PaceANN，核心目標是讓 DiskANN 在不重建索引布局的前提下，
以更低的磁碟讀取數和更早的無效展開停止條件，改善實務查詢效率。
PaceANN 的設計重點有兩個機制。
第一，它在原本的 DiskANN 搜尋路徑上加入一層\textbf{熱門度自適應快取管理器}（Popularity-Adaptive Cache Manager, PAC）：
以分片式 CLOCK 結構在查詢期間依實際存取熱點演化，並在快取項目中與鄰居列表共存全精度向量；
快取未命中時直接退回原本的磁碟讀取路徑，搜尋語義不變。
第二，它在 beam search 中加入 per-query 的\textbf{收斂感知早停}（Convergence-Aware Early Termination, CA-ET），
以已收斂候選的精確距離判斷是否可停，使 easy query 更早停下、hard query 繼續展開，
避免所有查詢都被同一個固定預算綁住\cite{li2020adaptiveet,chatzakis2025darth,teofili2025patience}.

本論文的主要貢獻如下：
\begin{itemize}
  \item 提出熱門度自適應快取管理器（PAC）：分片 CLOCK 加座標共存，在高並發下以低鎖競爭將熱點鄰居維持於 DRAM，並消除 re-rank 的 SSD I/O。
  \item 設計 per-query 的收斂感知早停（CA-ET）：以跨尺度精確門檻（PQ 下界對比第 $2k$ 名的精確距離）加 patience 計數，讓查詢依收斂狀態提前停止，且不額外觸發任何 I/O。
  \item 論證 PAC 與 CA-ET 的協同必要性，並在並發服務、iso-recall 與等記憶體預算下完成評估。% TODO(定稿數字)：填入去污染後對 DiskANN／Starling／PipeANN 的具體結果
  \item 分析記憶體與並發下的行為，說明兩個機制的協同效果，以及高並發下 shard contention 的界限。
\end{itemize}
