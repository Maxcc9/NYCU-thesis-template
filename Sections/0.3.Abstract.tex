    \textbf{Abstract} \\[0.5cm]
\end{center}

\normalsize

Approximate nearest neighbor search (ANNS) is a core component of vector databases, retrieval, and recommendation systems.
At the hundred-million scale the index no longer fits in memory, making disk-based graph indexes such as DiskANN the mainstream approach;
however, when a server concurrently handles many clients, the large volume of in-flight queries drives the SSD queue depth too high,
producing tail latency that violates service-level agreements (SLAs).
We identify two root causes. First, multi-user queries exhibit temporal locality: the hot nodes drift as the query distribution changes,
yet a static breadth-first (BFS) cache cannot adapt, so hot nodes traversed by many queries are read from disk repeatedly.
Second, although an easy query has already converged, beam search keeps expanding until the search budget is exhausted,
incurring unnecessary SSD I/O and lengthening the queue wait of other queries; both effects worsen tail latency and throughput.
To address these, we propose PaceANN, an acceleration scheme for disk-based ANNS that requires no index rebuild and applies directly to existing DiskANN indexes.
On the DRAM-over-SSD storage hierarchy, PaceANN introduces two co-designed mechanisms.
The first is a Popularity-Adaptive Cache Manager (PAC): a sharded CLOCK structure that \emph{dynamically} accumulates and updates the data of frequently visited nodes
according to the evolving hotspots at query time, raising the cache hit rate.
The second is Convergence-Aware Early Termination (CA-ET), which decides a per-query stopping point inside the beam-search loop from the convergence between the current candidates and the query,
so that easy queries stop early while hard queries keep expanding, reducing unnecessary SSD I/O and freeing SSD queue slots.
