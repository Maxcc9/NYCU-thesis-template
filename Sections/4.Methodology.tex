%=============================================================
\chapter{Methodology}
\label{ch:method}
%=============================================================

% ─── 章節破題 ───────────────────────────────────────────────
本章說明如何設計實驗以回答第~\ref{ch:motivation}~章提出的四個研究問題。
一個好的實驗設計必須同時滿足三個條件：
可重現性（所有關鍵參數均有明確記錄）、
公平性（對照系統在同等資源限制下比較）、
以及可解釋性（每個實驗的結論能夠獨立歸因，而非多個因素同時變動）。
PaceANN 的評估涉及三個在架構上有本質差異的系統，
公平性問題尤為關鍵，本章以獨立節次（§\ref{sec:fairness}）專門討論。

%-------------------------------------------------------------
\section{實驗假設與 RQ 對應}
\label{sec:hypotheses}
%-------------------------------------------------------------

每個子實驗對應第~\ref{ch:motivation}~章的一個研究問題，
並有明確的可驗證假設：

\begin{description}
  \item[\textbf{E1}（對應 RQ1）]
    \emph{PQ 距離比值能否可靠偵測 beam search 的收斂？}
    假設：在相同 recall 目標下，啟用 ET（$\theta > 0$）的平均 SSD I/O 數顯著低於停用 ET；
    且 recall 損失隨 $\theta$ 單調遞增。

  \item[\textbf{E2}（對應 RQ2）]
    \emph{快取覆蓋如何影響 ET 的觸發可靠性？}
    假設：在快取命中率較高的 warm BNC 條件下，
    相同 $\theta$ 的 recall 損失低於 cold cache 條件，
    即快取覆蓋是 ET 可靠性的前提條件。

  \item[\textbf{E3}（對應 RQ3）]
    \emph{在等記憶體預算下，PaceANN 的 QPS-recall Pareto 是否優於 Starling？}
    假設：在 30\% 原始資料大小的記憶體預算內，
    PaceANN 在 recall $\geq 0.95$ 的區間達到更高 QPS，
    且 P99 延遲不劣於 Starling。

  \item[\textbf{E4}（對應 RQ4）]
    \emph{$\theta$ 的最優值在不同 recall 目標下如何變化？}
    假設：存在一個資料集相關的最優 $\theta^*$，
    使 QPS-recall trade-off 最佳化；
    $\theta^*$ 與 PQ 壓縮誤差分布相關，可透過掃描估計。
\end{description}

\section{資料集與索引設定}
\label{sec:dataset}
%-------------------------------------------------------------

\paragraph{SIFT100M}

主要實驗使用 SIFT100M 資料集：
1 億筆 128 維 \textbf{uint8} 向量，
原始大小 $100\,\text{M} \times 128\,\text{B} = 12.8\,\text{GB}$。
選擇此資料集的理由如下：

\begin{enumerate}
  \item 規模足夠大（$10^8$），使 SSD 儲存不可避免——即使是 64\,GB 的實驗機器
    也無法在 30\% 記憶體預算下完整保留向量索引。
  \item 資料型別為 \textbf{uint8}，與生產環境的圖像特徵向量一致，
    避免 float32 對結果造成的偏移（注意：SIFT1M 為 float32，不可混用）。
  \item 學術社群有廣泛使用，方便與文獻結果交叉比對。
\end{enumerate}

查詢集使用官方 10,000 筆 query，ground truth 為 top-10 精確最近鄰（歐氏距離）。
所有量測均使用完整 10,000 筆 query（$n_\text{total} = 10000$），
不做截斷，以確保 recall 估計的統計穩定性。

$R = 96$ 的設定在圖密度與索引大小之間取平衡：
$R = 128$ 雖可提供更豐富的連接，但 sector 大小固定，
更高的 $R$ 意味著更多 sector 讀取，反而可能降低 I/O 效率。

\paragraph{Starling 索引設定}

Starling 使用相同的圖建構參數（$R = 96$，$L_\text{build} = 120$），
但額外執行 block shuffling 步驟，
將相鄰節點打包於同一磁碟頁面（page size = 2）。
Navigation graph（mem-index）以 $R_\text{mem} = 20$、
$L_\text{mem} = 128$ 建構，
涵蓋 0.1\% 的隨機採樣節點。

需要特別說明的是，Starling 的索引格式與 DiskANN \textbf{不相容}：
兩者不能使用同一個索引檔案，
因此兩者的 graph quality 在建構細節上仍有微小差異。
這是現有評估方法論的不可避免限制，
本研究在呈現比較結果時均明確標記此點。

\section{公平性協定：記憶體預算正規化}
\label{sec:fairness}
%-------------------------------------------------------------

PaceANN 與 Starling 在架構上的根本差異在於：

\begin{itemize}
  \item DiskANN / PaceANN 的最小啟動記憶體僅需 PQ 壓縮向量（約 1.74\,GB），
    剩餘預算可彈性分配給 BNC。
  \item Starling 在啟動時強制載入 \texttt{partition.bin}（827\,MB）到兩個記憶體結構
    （\texttt{id2page\_} 約 400\,MB、\texttt{gp\_layout\_} 約 400\,MB），
    加上 navigation graph（約 31\,MB），
    最小 RSS 固定為 \textbf{3.07\,GB}，無法降低。
\end{itemize}

若以固定絕對預算（例如「同為 3\,GB」）比較，
Starling 恰好用完而 PaceANN 還有餘裕，對 PaceANN 有利；
若以不同絕對預算分別取最優，
則兩者資源不等，比較失去意義。

\paragraph{30\% 原始資料大小作為標準預算}

本研究採用業界常見的記憶體預算基準：
\textbf{30\% 原始資料大小}。
對 SIFT100M（12.8\,GB），標準預算為 $0.3 \times 12.8 = 3.84\,\text{GB}$。

在此預算下：
\begin{itemize}
  \item \textbf{DiskANN baseline}：使用固定 1.74\,GB（低於預算，不調整）。
  \item \textbf{Starling}：固定使用 3.07\,GB（低於 3.84\,GB，在預算內）。
  \item \textbf{PaceANN}：BNC 設定為 1.65\,GB（總 RSS 約 3.55\,GB，在預算內）。
\end{itemize}

此配置讓三個系統均在 3.84\,GB 預算內，
且 PaceANN 與 Starling 的 RSS 相近（3.55\,GB vs. 3.07\,GB）。

\paragraph{暖機協定的對稱性}

兩個系統的快取暖機機制存在本質差異：

\begin{itemize}
  \item \textbf{PaceANN BNC}：需求驅動，初始命中率為零，
    必須以代表性查詢集執行 warmup 才能達到穩態。
    本研究以 10,000 筆 warmup query（L=100）填充 BNC，
    再執行量測（\textbf{warm BNC} 條件）。
  \item \textbf{Starling mem-index + partition.bin}：
    啟動時即完整載入，無需 warmup。
    其 10,000 筆 warmup 查詢對 Starling 記憶體狀態幾乎無影響，
    僅用於穩定 OS 的 page cache 與 TLB。
\end{itemize}

為確保比較的公平性，兩個系統均執行相同數量的 warmup query，
但需理解 warmup 對兩者的實際效果不同。
所有論文中呈現的結果均為 warmup 完成後的穩態量測。

\paragraph{執行緒數對稱}

所有對照系統均設定 $T = 16$ worker thread，
beam width $W$ 依各系統最優設定（
DiskANN / PaceANN 使用 $W = 8$；
Starling 使用 $W = 4$，與其原論文設定一致）。

\section{量測方法論}
\label{sec:measurement}
%-------------------------------------------------------------

\paragraph{Server-side 延遲量測}

所有延遲數字（mean、P50、P99、P999）均在 \textbf{server 端}計算，
時間戳從 worker thread \emph{完整接收查詢封包後}開始，
到返回結果封包前結束。
此設計排除了 TCP 連線建立與網路傳輸時間，
使延遲數字反映搜尋演算法本身的成本，而非網路延遲。

QPS（每秒查詢數）在 \textbf{client 端}以牆鐘時間計算，
從發出第一個 query 到收到最後一個 query 回應，
反映端到端的系統吞吐量。

\paragraph{並發數掃描}

主要結果以並發數 $C \in \{1, 8, 32\}$ 呈現：
$C = 1$ 代表單一客戶端的串列延遲基準，
$C = 8$ 代表中等並發的典型 server 負載，
$C = 32$ 代表高並發壓力測試（$C > T$，存在查詢排隊）。
$C = 8$ 是主要 QPS 比較指標，因其吞吐量與尾延遲皆處於有意義的工作點。

\paragraph{Search list size $L$ 的角色}

$L$（beam search 的候選列表大小）是控制 recall 的主要旋鈕：
$L$ 越大，recall 越高，但每次查詢的 hop 數與 I/O 量越多。
通過掃描 $L$，可以在 recall 軸上生成 QPS-recall Pareto 曲線。
本研究使用 $L \in \{20, 30, 50, 80, 100, 150, 200, 250, 300\}$ 的掃描範圍，
覆蓋 recall 約 0.60 到 0.99 的區間。

\section{$\theta$ 參數敏感性研究}
\label{sec:theta-sweep}
%-------------------------------------------------------------

ET 的核心參數 $\theta$ 決定停止條件的保守程度。
本研究以以下方法論系統化地確定其最優設定範圍：

\paragraph{掃描設計}

固定 BNC 容量為 1.65\,GB（warm 條件），
掃描 $\theta \in \{1.05, 1.10, 1.12, 1.20, \infty\}$（$\infty$ 代表停用 ET），
對每個 $\theta$ 值執行完整的 $L$-sweep（$L \in \{20, 30, 50, \ldots, 300\}$），
記錄 QPS、Recall@10 與 \textbf{MeanIOs}（每次查詢的平均 SSD I/O 數）。

MeanIOs 是關鍵的中間指標：
它量化 ET 實際阻止了多少 SSD 讀取，
使 QPS 改善的原因可以歸因於「更少 I/O」而非其他因素。

\paragraph{Pareto 最優 $\theta$ 的定義}

對每個 recall 閾值 $r^*$（例如 $r^* = 0.95$），
定義 Pareto 最優 $\theta$ 為：

\begin{equation}
  \theta^*(r^*) = \argmax_{\theta} \text{QPS}(\theta, L^*(r^*,\theta))
  \quad \text{subject to } \text{Recall}(\theta, L^*(r^*,\theta)) \geq r^*
  \label{eq:theta-opt}
\end{equation}

其中 $L^*(r^*, \theta)$ 是在給定 $\theta$ 下達到 recall $r^*$ 所需的最小 $L$。
此定義避免了「用更大的 $L$ 補償激進 $\theta$ 造成的 recall 損失」的人為對比偏差。

\paragraph{$\theta$ 與 PQ 壓縮誤差的關係分析}

從理論上，$\theta$ 的容忍帶應與 PQ 的量化誤差分布成正比：
若 PQ 的距離估計偏差較大，$\theta$ 應設得更保守（更大）；
偏差較小時，$\theta$ 可以接近 1.0。
本研究透過比較不同 $\theta$ 下的 recall 下降速率，
推斷本實驗 NVMe-SIFT100M 設定下的等效 PQ 誤差容忍帶，
為未來其他資料集的 $\theta$ 選擇提供參考。

\section{量測指標定義}
\label{sec:metrics}
%-------------------------------------------------------------

\begin{description}
  \item[Recall@10]
    $|S_{10}(q) \cap G_{10}(q)| \;/\; 10$，
    其中 $S_{10}(q)$ 為系統返回的 top-10，$G_{10}(q)$ 為 ground truth top-10。
    以 10,000 筆 query 的算術平均值報告。

  \item[QPS（Queries Per Second）]
    $n_\text{total} / T_\text{wall}$，
    以 client 端牆鐘時間計算，
    包含 TCP 傳輸延遲（通常 $< 0.1\,\text{ms}$，在 localhost 模式下可忽略）。

  \item[Server-side Latency（Mean / P50 / P99 / P999）]
    以 server 端的處理時間計算（不含 TCP 傳輸）。
    P99 與 P999 是評估尾延遲行為的主要指標，
    對應 SLA 中「99\% / 99.9\% 請求須在時限內完成」的要求。

  \item[MeanIOs]
    每次查詢觸發的 SSD 讀取次數的平均值（不含快取命中）。
    此指標僅適用於 PaceANN（DiskANN 系），
    用於量化 ET 的 I/O 節省效果。

  \item[RSS（Resident Set Size）]
    Server process 在量測期間的常駐記憶體大小，
    以 \texttt{/proc/\$PID/status} 的 \texttt{VmRSS} 欄位讀取。
    用於驗證實際記憶體用量是否在 30\% 預算內。
\end{description}

\section{可重現性說明}
\label{sec:reproducibility}
%-------------------------------------------------------------

為便於結果重現，所有 benchmark 腳本均以 shell script 形式保存，
包含明確的 server 啟動命令、warmup query 數量、並發數設定與輸出 CSV 格式。
每次 server 啟動後均等待 35\,秒（PaceANN）或 90\,秒（Starling，需額外載入 BFS cache）
以確保 index 完整載入後才開始量測。

索引建構使用固定隨機種子，確保 Vamana 圖的可重現性。
Starling 的索引在獨立機器上建構後以 \texttt{rsync} 傳輸，
其 medoid 節點（25,384,254）與 DiskANN 索引（94,370,396）不同，
此差異已在分析中明確標記。
