\section{Disk-based Graph ANN}

高維向量的近似最近鄰搜尋方法一般依索引結構分為四類：樹狀\cite{muja2014flann}、雜湊\cite{datar2004lsh}、聚類式\cite{chen2021spann} 與圖式\cite{malkov2020hnsw,fu2019nsg}. 樹狀方法在低維有效，但隨維度上升會因維度詛咒而退化；雜湊以機率性方式把相近向量映到同一桶；聚類式將向量分群、以反向索引只在少數群內搜尋；圖式方法則在多項實證中於效率與精度的取捨上最佳，成為高維向量搜尋的主流。乘積量化（PQ\cite{jegou2011pq} 及其優化版 OPQ\cite{ge2013opq}）並非獨立的索引結構，而是可跨類別套用的向量壓縮技術，常用於降低記憶體與計算成本，DiskANN 等磁碟式系統即以其壓縮導航向量。然而記憶體內的圖式索引須同時保存原始向量與圖結構，記憶體開銷高，難以擴展到數億級以上的資料\cite{subramanya2019diskann}.

DiskANN 以 Vamana 圖搭配 PQ 壓縮碼突破此限制：壓縮向量留在記憶體導航、完整索引置於磁碟，在單機支援十億級搜尋\cite{subramanya2019diskann}，並已落地於實際的向量資料庫與雲端服務\cite{wang2021milvus,upreti2025cosmos}. 沿此圖式磁碟路線，DiskANN++ 以 query-sensitive 入口與 page-based traversal 進一步降低搜尋成本\cite{ni2023diskannpp}. 這些系統共享同一個瓶頸：beam search 的關鍵路徑包含數十次隨機磁碟 I/O，使磁碟式圖索引的查詢延遲遠高於記憶體內索引。針對此瓶頸，PipeANN 以 compute-I/O pipelining 對齊 best-first 搜尋與 SSD 特性，重疊每一步的計算與 I/O，藉此縮短單筆查詢的關鍵路徑延遲\cite{osdi25pipeann}. PipeANN 與本研究處理同一瓶頸的不同面向：它針對\emph{單筆}搜尋的延遲進行排程層級的重疊，而 PaceANN 則在\emph{高並發}下直接減少進入共享佇列的冗餘 I/O 總量；兩者機制正交，也因此 PipeANN 是本研究在 serving 情境下的主要對照系統之一。

此瓶頸的結構直接來自 DiskANN 的磁碟佈局（圖~\ref{fig:diskann-layout}）：每個節點是一筆定長記錄，依序存放全精度向量、鄰居數與定長鄰居 ID 列表，多筆節點打包進固定大小的 sector。因此每展開一個節點即一次 4\,KB 隨機讀取，而末段 re-rank 所需的全精度向量保存於同一記錄中；查詢成本因而由「展開幾個節點」與「其中幾個須回盤」共同決定——這也是 PaceANN 兩個機制各自針對的目標。

\section{Page Layout and Search Reordering}

減少讀取的 page 數不足以消除 I/O 瓶頸，還須提高每次讀取的資訊密度。Starling 以 block shuffling 將鄰近節點打包進同一 page，並以取樣資料建立記憶體導航圖縮短搜尋路徑，在靜態索引與中等 recall 下取得顯著加速\cite{wang2024starling}；Select Edges Wisely 則以單調路徑感知的圖布局進一步壓低磁碟 I/O\cite{yue2025selectedges}. 這類方法的效益依賴離線重排與靜態布局假設：資料更新時新節點無法即時享有重排後的 locality，記憶體預算下降時導航圖品質亦隨之退化、搜尋路徑變長。因此其在固定測試設定下表現亮眼，卻不一定適合更新頻繁或資源受限的生產工作負載。

\section{Early Termination for ANN Search}

固定搜尋預算對難易查詢一視同仁，在 easy query 上浪費 hops、在 hard query 上損及 recall。針對此已有多種 query-adaptive 早停：以學習模型預測終止點\cite{li2020adaptiveet}、以宣告式 recall 目標驅動停止\cite{chatzakis2025darth}、以 top-$k$ 結果穩定性為判據\cite{teofili2025patience}、以距離自適應調整 beam 寬並給出正確性保證\cite{aljazzazi2025dabs}，或依查詢分布調整探索策略\cite{zhang2025distributionaware}. 這些方法多在記憶體內索引（如 HNSW）上驗證，其終止判斷未與磁碟式系統的 I/O 路徑與快取共同設計，因此難以直接把「少發 I/O」轉化為 serving 下的吞吐與尾延遲改善。

\section{Positioning of PaceANN}

PaceANN 不重建索引布局，也不取代圖式或 page-based 方法，而是在保留 DiskANN 索引語義的前提下，直接針對「高並發下冗餘 I/O 灌入共享 SSD 佇列」這個 serving 瓶頸。與 Starling 相比，它不依賴新的靜態 page layout，改以隨工作負載演化的動態快取涵蓋各查詢專屬、且隨分布漂移的收斂熱區；與既有早停相比，它把 frontier 與 top-$k$ 的跨尺度比較嵌入 DiskANN 的 beam search 主迴圈，並與快取共同設計，使收斂端的終止信號可靠。這種設計使 PaceANN 特別適合高 recall、需 server 端並發處理、且資料頻繁更新的部署情境。
